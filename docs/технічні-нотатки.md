```
Уся часова база проєкту рахується від 170 МГц: один такт таймера = 5.882 нс.

TIM2 (вхід, період 34 такти = 200 нс = 5.000 МГц):
CH1 (PA0) - CLK для АЦП, PWM1, CCR1 = 17 -> шпаруватість рівно 50 %.
CH2 (без виходу) - генератор запиту DMA, CCR2 = 12 -> 70.6 нс після
наростаючого фронту CLK. Запит не дорівнює читанню: DMA ще витрачає
20...45 нс на арбітраж, тому шина реально зчитується на 90...115 нс -
це середина вікна, де дані АЦП вже дійсні і ще не змінилися.

TIM3 (вихід, період 102 такти = 600 нс = 1.6667 МГц):
102 = 3 * 34, тобто на кожні три вхідні семпли припадає рівно один
вихідний. Співвідношення 3:1 задане апаратно і не може "поїхати".
UPDATE -> запит DMA на запис у ODR.
CH1 (PA6) - строб засувки ЦАП, PWM2, CCR1 = 51 -> наростаючий фронт
через 300 нс після оновлення даних. PWM2 узятий саме тому, що в PWM1
наростаючий фронт збігся б з UPDATE, тобто з моментом запису даних.
```

```
Пріоритет VERY_HIGH саме у вхідного каналу: пропущений семпл АЦП
втрачений назавжди, тоді як затримка виводу лише зсуне фронт на ЦАП.
```

```
MEMORY_TO_PERIPH тут принципово: HAL_DMA_Start розкладає адреси за
напрямком, і при PERIPH_TO_MEMORY масив пішов би в CPAR, а регістр ODR -
у CMAR з інкрементом, тобто DMA затирав би регістри GPIO.
```
